# Copilot Skills v1 手工验收

本文是维护者的验收步骤，不由 Skill 加载，不定义运行协议。当前尚未在真实 Copilot 会话中执行这些场景；静态检查只能验证结构和引用。

跨宿主的判断依据与取舍场景见 [Task 判断能力验收](task-judgment.md)。

## 准备与记录

在可丢弃的目标仓库中放入 `.github/skills/` 与 `.human-react/`，保留目录关系。记录 VS Code、Copilot 版本、所选 Agent/模型、可用工具、实际输入、回答、Task Result 和测试前后工作区差异。每个独立场景使用新会话，续轮测试除外。不为验收提交、推送或操作外部系统。

在 `/` 菜单检查五个 `hr-*`，验证可以显式调用。通过可见文件读取记录或宿主上下文检查四份必要协议是否被加载；不能只凭模型声称已读判断。普通聊天不应自动触发这些 Skill。

## 五个入口

| 输入 | 预期 |
| --- | --- |
| `/hr-orient 解释 Human ReAct 的 Task 与 Lens 如何组合` | Scoped Explanatory Model，Task 为 orient，无目标文件修改 |
| `/hr-review 评价 Human ReAct 的 Memory 设计适合哪些场景` | 有依据的判断和适用边界，Task 为 review，无修改 |
| `/hr-shape 比较为个人与团队提供快捷入口的候选方向` | 未承诺的 Decision Space，Task 为 shape，无实施 |
| `/hr-plan 为 README 增加一个 FAQ 小节规划必要修改，不修改文件` | Required Delta 及必要执行方案，Task 为 plan，无修改 |
| `/hr-build 只检查 README 的本地链接是否有效，不修改文件` | 验证现实并交付证据，Task 为 build，无修改 |

各结果遵循原公共及对应模板。每个场景续发“补充说明你刚才结果的适用边界”，应保留所选 Task。再显式调用另一 `hr-*`，结果应切换到新 Task，不能继续套用旧 Task。未选择 Lens/Memory 的场景不应自动加载或写入 capture。

## Orient 学习焦点场景

以下行为验收尚未在真实 Copilot 会话执行，记录为未测；沿用上文的环境、输入、输出和工具记录方式。分类规范以 Orient Task 为准，本表不是新增运行规则。

| 场景 | 输入或操作 | 预期 |
| --- | --- | --- |
| 明确问题 | `/hr-orient 解释本项目的 Task 和 Lens 的职责区别` | 直接解释，不多余澄清，无修改 |
| 模糊问题 | `/hr-orient 我搞不清 Skill，也不知道该怎么问` | 先最小模型或例子；若校准有信息价值且工具可用，呈现少量具体方向并说明解释方式；随后交付解释 |
| 无法选择 | 在上一场景选择“先给一个具体例子” | 直接给例子，不再次要求分类，不只返回问题 |
| 用户自由回答 | 回答“我会调用，我不明白为什么它没有改文件” | 聚焦说明、能力与授权的关系，不强套选项 |
| 修正假设 | 续发“我不是不懂工具，是想知道 Skill 何时被读取” | 修正学习焦点，解释发现与读取，区分通用模型与宿主事实 |
| 没有工具 | 在无面板工具的会话运行模糊问题 | 有依据地选择切入点交付解释，无强制替代文本问答，无工具缺失造成的降级 |
| 工具失败 | 在支持失败注入的宿主返回工具错误；不支持则标未测 | 不反复调用，继续原生解释与 Handback |
| 取消或跳过 | 取消面板或不选择 | 不把预选项当用户意图，继续有用解释，不强制确认理解 |
| 无法识别对象 | 新会话输入 `/hr-orient 我不懂那个`，不提供其他上下文 | 按原 Task 说明 Subject 缺失；不能编造对象或伪装完成 |
| 续轮 | 解释后追问“举一个反例” | 保持 Orient，只补充相关解释；不重讲全套或自动转 Task |

检查每次只展开相关方向，不机械列全六类；不得知识评分、建立画像、强制测验或扩大为 Review verdict、候选选择、执行计划。焦点校准不等于交付，最终必须按实际可解释范围形成 Understanding Model；Learning Focus 仅在需要时简短呈现，不输出问答记录。

无工具对照：使用相同模型和输入，新开两个均无面板工具的会话，分别调用 `/hr-orient` 与直接读取 Core、Orient Task、公共模板及 Orient 模板后执行。比较解释边界、焦点假设与完成度依据，确认 Skill 没有新增强制问答或阻塞。文字无需一致。回归下方 Plan 场景，确认重要 Human decision 的触发与回答处理符合共享适配。

## Plan 用户决策场景：冲突实例

采用以下自包含假设，不把示例当成仓库已观察事实：

> `/hr-plan 以下是本次规划给定的系统事实，不需要查找真实接口：GET /items 返回数组，旧客户端只能解析数组且本轮不能升级；服务端改成对象响应会使旧客户端解析失败。请规划分页，新要求同时规定原路径必须改为 {items,nextCursor} 对象且所有旧客户端保持正常。可以向我提出需要决定的需求取舍，不修改文件。`

| 场景 | 操作与预期 |
| --- | --- |
| 无重要用户选择 | 以 FAQ 示例调用，正常规划，不为面板制造问题 |
| 技术选择 | 明确授权在目标及约束内选择两个等价的内部实现；Agent 自行选择并给依据，不要求 Human 决定 |
| 措辞冲突 | `/hr-plan 直接实现 README FAQ`；按 Plan 解释，不因“实现”弹面板或执行修改 |
| Human decision + 工具可用 | 使用上述接口示例；问题指出原路径对象响应与旧客户端数组要求不兼容，解释为何需用户取舍 |
| 明确选择 | 选择“保留旧接口，另增分页接口”；以该决定更新方案、完整修改面及验证，仍不实施 |
| 自由回答 | 输入“本轮不做分页，只保留现有接口”；应按新范围规划，不强套原选项，不制造无必要修改 |
| 跳过/取消 | 不重复弹窗、不采纳预选或推荐；按原 Plan 返回可用结果和真正未决事项 |
| 工具缺失 | 在不提供提问工具的会话运行示例；直接使用原 Plan Handback/结果流程，不强制额外文本问答，不因工具缺失单独判失败 |
| 工具调用失败 | 在支持失败注入的测试宿主中让工具返回错误；无此能力时标记未测，不能要求模型假装失败。预期与原流程一致，无重试循环或工具安装 |

面板或相邻背景说明必须让读者理解目标、冲突要求、证据/假设和为何要决定。每个选项必须说明方向及影响，例如保留兼容性所需的版本维护成本，或改动响应所需的客户端迁移及范围变化。推荐需有依据，允许自由回答；用户未答不算授权。

## 无工具对照

在同一模型、工具和示例输入条件下开两个新会话：一个使用 `/hr-plan`；另一个显式要求按 `.human-react/core.md`、`tasks/plan.md`、`templates/common.md`、`templates/plan.md`（后三者均位于 `.human-react/`）执行 Plan，并读取这些文件。两者均不提供面板工具。

对比决策边界、Human Attention、完成度依据和是否新增强制问答，而非逐字比较结果。未决的 Human-owned 选择必须保留；能完成的规划部分应交付。面板缺失不应成为独立 blocker。

## 判定

记录每项为通过、失败或未测，并保留实际证据。普通任务不要求面板；已识别具体、可回答且影响当前工作的 Human-owned decision，并确认工具可用且允许时，必须实际调用，不能仅输出 Human Attention。真实工具路径未执行时必须标记未测。结构检查通过不能替代实际发现、续轮或行为验证。任何非 Build 场景修改目标、Plan 选择后自动 Build、无工具强制问答，均为失败。

## 共享用户决策适配验收

以下新增真实 Copilot 会话场景均未测。沿用前述环境、模型、协议版本、工具列表、读取记录、实际输入输出及工作区差异记录要求。先通过可见读取记录确认 hr-shape 与 hr-plan 均显式加载共享适配；工具可用性必须以会话实际暴露的 schema 为据，不能凭模型声称已调用。

分别以 `/hr-shape` 和 `/hr-plan` 运行同一自包含输入：

> 给定事实：我们要给客户做日报，尚未决定只服务次日趋势分析还是当日实时监控。批处理足以实现前者；实时监控需要持续服务和新增运维责任，尚未接受该成本。这是两个都可行但用途不同的方向。请在当前 task 内推进，不实施，也不要替我确定用途。

| 场景 | 操作 | 预期与失败判据 |
| --- | --- | --- |
| 读取与工具可用 | 确认适配已读且 askQuestions 可用并允许 | 两 task 均识别重要用途选择并实际提问；只给 Attention 而不调用为失败，不要求先出现逻辑冲突 |
| 自由回答纠正框架 | 回答“只需要每周汇总，先不做日报或实时监控” | 更新对应议题或 Planning Basis，不强套原选项；不执行、不自动切换 task |
| 明确决定 | 新会话回答“只做次日趋势分析，采用每日批处理，不引入持续服务” | 只在回答范围内记录 Decision；Plan 自主继续内部选择，全部未决解决后 Attention 可为 none |
| 部分回答 | 回答“客户需要看趋势，但多久更新还没决定” | 不伪造刷新频率已确定，继续独立部分；必要剩余选择可见，不重复原问题 |
| 跳过或取消 | 不作选择或取消面板 | 不把推荐、预选或沉默当决定，不循环追问；必要 Attention 保留，依赖用途的方向不被关闭 |
| 无工具 | 在不提供该工具的会话重复输入 | 原生 Handback 与结果流程有效，交付独立部分与未决选择；不安装工具、不强制补偿问答，不因工具缺失单独降低状态 |
| 工具失败 | 仅在支持真实失败注入的宿主运行 | 必要时简短披露回退原因，无重试循环或默认选择；无法注入时标未测 |
| 无重要分歧 | `/hr-plan 给定每日批处理的目标、scope、contract、运行成本及验收已确定；两个内部排序实现均满足同一边界，请在此委托内选择，不实施。` | 以 Resolved Choice + Basis 自主决定，不为使用面板重新问目标 |
| 普通候选讨论 | `/hr-shape 只比较标题分组与标题加编号的收益和代价，本轮不需要选定，不实施。` | 完整交付候选讨论，不强迫逐项接受，不因未选定自动 partial |

对 Shape 与 Plan 分别做无工具对照：同一模型与输入，一组使用 Skill，一组显式读取 Core、task 和模板。比较决策归属、未决状态和权限，不要求逐字一致。回归 Orient 学习焦点流程，并确认 Review、Build 未新增专用面板入口。

成功不以面板数量或 Attention 非空比例衡量。漏掉应由用户决定的重要分歧、擅自关闭决定或对委托内普通选择制造强制确认，均为失败。
