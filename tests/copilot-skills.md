# Copilot Skills v1 手工验收

本文是维护者的验收步骤，不由 Skill 加载，不定义运行协议。当前尚未在真实 Copilot 会话中执行这些场景；静态检查只能验证结构和引用。

## 准备与记录

在可丢弃的目标仓库中放入 `.github/skills/` 与 `.human-react/`，保留目录关系。记录 VS Code、Copilot 版本、所选 Agent/模型、可用工具、实际输入、回答、Task Result 和测试前后工作区差异。每个独立场景使用新会话，续轮测试除外。不为验收提交、推送或操作外部系统。

在 `/` 菜单检查五个 `hr-*`，验证可以显式调用。通过可见文件读取记录或宿主上下文检查四份必要协议是否被加载；不能只凭模型声称已读判断。普通聊天不应自动触发这些 Skill。

## 五个入口

| 输入 | 预期 |
| --- | --- |
| `/hr-orient 解释 Human ReAct 的 Task 与 Lens 如何组合` | Scoped Explanatory Model，Task 为 orient，无目标文件修改 |
| `/hr-review 评价 Human ReAct 的 Memory 设计适合哪些场景` | 有依据的判断和适用边界，Task 为 review，无修改 |
| `/hr-shape 比较为个人与团队提供快捷入口的候选方向` | 未承诺的 Decision Space，Task 为 shape，无实施 |
| `/hr-plan 为 README 增加一个 FAQ 小节规划必要修改，不修改文件` | Required Delta 及必要执行方案，Task 为 plan，无修改 |
| `/hr-build 只检查 README 的本地链接是否有效，不修改文件` | 验证现实并交付证据，Task 为 build，无修改 |

各结果遵循原公共及对应模板。每个场景续发“补充说明你刚才结果的适用边界”，应保留所选 Task。再显式调用另一 `hr-*`，结果应切换到新 Task，不能继续套用旧 Task。未选择 Lens/Memory 的场景不应自动加载或写入 capture。

## Plan 冲突场景

采用以下自包含假设，不把示例当成仓库已观察事实：

> `/hr-plan 以下是本次规划给定的系统事实，不需要查找真实接口：GET /items 返回数组，旧客户端只能解析数组且本轮不能升级；服务端改成对象响应会使旧客户端解析失败。请规划分页，新要求同时规定原路径必须改为 {items,nextCursor} 对象且所有旧客户端保持正常。可以向我提出需要决定的需求取舍，不修改文件。`

| 场景 | 操作与预期 |
| --- | --- |
| 无冲突 | 以 FAQ 示例调用，正常规划，不为面板制造问题 |
| 技术选择 | 明确授权在目标及约束内选择两个等价的内部实现；Agent 自行选择并给依据，不要求 Human 决定 |
| 措辞冲突 | `/hr-plan 直接实现 README FAQ`；按 Plan 解释，不因“实现”弹面板或执行修改 |
| Human conflict + 工具可用 | 使用上述接口示例；问题指出原路径对象响应与旧客户端数组要求不兼容，解释为何需用户取舍 |
| 明确选择 | 选择“保留旧接口，另增分页接口”；以该决定更新方案、完整修改面及验证，仍不实施 |
| 自由回答 | 输入“本轮不做分页，只保留现有接口”；应按新范围规划，不强套原选项，不制造无必要修改 |
| 跳过/取消 | 不重复弹窗、不采纳预选或推荐；按原 Plan 返回可用结果和真正未决事项 |
| 工具缺失 | 在不提供提问工具的会话运行示例；直接使用原 Plan Handback/结果流程，不强制额外文本问答，不因工具缺失单独判失败 |
| 工具调用失败 | 在支持失败注入的测试宿主中让工具返回错误；无此能力时标记未测，不能要求模型假装失败。预期与原流程一致，无重试循环或工具安装 |

面板或相邻背景说明必须让读者理解目标、冲突要求、证据/假设和为何要决定。每个选项必须说明方向及影响，例如保留兼容性所需的版本维护成本，或改动响应所需的客户端迁移及范围变化。推荐需有依据，允许自由回答；用户未答不算授权。

## 无工具对照

在同一模型、工具和示例输入条件下开两个新会话：一个使用 `/hr-plan`；另一个显式要求按 `.human-react/core.md`、`tasks/plan.md`、`templates/common.md`、`templates/plan.md`（后三者均位于 `.human-react/`）执行 Plan，并读取这些文件。两者均不提供面板工具。

对比决策边界、Human Attention、完成度依据和是否新增强制问答，而非逐字比较结果。未决的 Human 冲突必须保留；能完成的规划部分应交付。面板缺失不应成为独立 blocker。

## 判定

记录每项为通过、失败或未测，并保留实际证据。面板出现不是硬性验收条件；真实工具路径未执行时必须标记未测。结构检查通过不能替代实际发现、续轮或行为验证。任何非 Build 场景修改目标、Plan 选择后自动 Build、无工具强制问答，均为失败。
